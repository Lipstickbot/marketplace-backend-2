# Покупка доступа к агенту

Платные карточки хранят цену в `agents.price_minor` в тиынах. Пустое значение оставляет обычное подключение. Keme AI поддерживает разовую покупку в KZT. Цена для каждого платного агента задаётся оператором платформы. При изменении цены уже одобренные подключения продолжают действовать.

Кабинет открывает форму карты на стороне PayLink. Сервер сам запрашивает статус операции у PayLink и сверяет магазин, режим, сумму, валюту и номер заказа. После подтверждения Supabase в одной транзакции сохраняет покупку и открывает подключение для этой компании. Агент появляется в истории кабинета и доступен в настройке API и в форме запуска. Повторная проверка платежа возвращает тот же результат. Платформа не получает реквизиты карты.

## Тестирование и выпуск

- Миграция `20261126190000_agent_purchases.sql` добавляет цены и журнал покупок. Примените её к базе соответствующего окружения до деплоя.
- Автоматические тесты используют подставные ответы PayLink. Тестовые платежи провайдера не дают доступ через производственный маршрут.
- В рабочем окружении оплата выключена по умолчанию. Её включает уполномоченный оператор организации после одобрения магазина PayLink и проверки договора, условий возврата и обработки спорных операций. Серверные имена переменных указаны в `.env.example`. Для автоматической сверки уведомлений `PAYLINK_NOTIFICATION_BASE` указывает на публичный HTTPS-адрес бэкенда.
- При отмене оплаты пользователь может вернуться к агенту и проверить предыдущую попытку. При незавершённом заказе система переиспользует ссылку. При подтверждённом PayLink завершении без оплаты доступ остаётся закрыт и можно начать новый заказ.

Интеграция проводит продажу через один магазин Keme AI. Для выплат авторам и автоматической обработки возвратов или споров нужен отдельный сценарий.
