# Keme AI: интерфейс и серверная платформа

Исходный интерфейс: https://github.com/ayau8273/keme-ai. Версия зафиксирована в `frontend/UPSTREAM.md`. Изменения хранятся здесь; репозиторий автора не изменялся.

## Запуск

Нужны Python 3.13 и Node.js 22 с npm. Из корня установить зависимости Backend согласно README, затем:

```powershell
cd frontend
npm ci
npm run build
cd ..
.\scripts\start-backend.ps1
```

Открыть `http://127.0.0.1:8001/`. Backend раздаёт собранный сайт, каталог `/catalog/` и кабинет `/account/`. Браузер обращается к `/api/*` того же сервера; исходные API пути без префикса сохранены. При разработке `npm run dev` из `frontend` запускает Vite на порту 3000 с прокси к Backend на 8001.

Серверные ключи Supabase и движка остаются в корневом `.env` или переменных сервера. Во фронтенде их нет. `frontend/.env.example` содержит только публичный адрес API. Сессия пользователя хранится в localStorage этого браузера и сохраняется после его закрытия; пароль не сохраняется. Временные данные Google PKCE хранятся в sessionStorage вкладки. После входа и регистрации открывается главная. Кнопка «Выйти» удаляет сохранённую сессию. Ответы движка и загруженные данные выводятся как текст с экранированием HTML. POST запуска не повторяется автоматически.

## Потоки

- Каталог читает все страницы API: три демо и девять карточек «Скоро»; поиск, категории, RU/KK/EN и детали карточки. Главная сохраняет исходные анимации и дизайн.
- Вход, регистрация business/developer, подтверждение почты при включённом требовании, refresh и logout. Администратор назначается доверенным оператором базы.
- Бизнес отправляет запрос подключения; после одобрения запускает агента, загружает PDF/DOCX/TXT, выбирает документы, читает результат и историю, скачивает и удаляет свои файлы. Mock явно обозначен. Тексты результатов не восстанавливаются из истории.
- Разработчик отправляет заявку на публикацию и видит её статус.
- Администратор рассматривает подключения и публикации. Одобренная публикация создаёт карточку «Скоро»; сторонний код не исполняется.
- Формы главной больше не имитируют успешную отправку: требуют нужную роль и вызывают API. Заявка, начатая до входа, сохраняется во вкладке и отправляется только после явного подтверждения в кабинете.

Кабинет пока на русском языке; главная и каталог сохраняют RU/KK/EN. Настройки пользователя, оплата, команды и восстановление пароля не добавлялись.

## Облачное размещение

Корневой `Dockerfile` собирает Vite и запускает FastAPI со статическими файлами на порту 8001. Создать отдельный Web Service Backend 2 из этого репозитория с Runtime Docker и Health Check `/health`; AI Engine друга остаётся отдельным сервисом. Перед запуском задать серверные `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `ENGINE_URL`, `ENGINE_JWT_SECRET`, `ENGINE_JWT_AUDIENCE`, `ENGINE_JWT_ISSUER`. Секреты задавать через настройки хостинга. Изменение origin для отдельного размещения фронтенда требует явного `CORS_ORIGINS` у Backend.

Общий сайт опубликован: **https://keme-ai-platform.onrender.com**. Docker-сборка на Render успешна; 37 проверок прошли через публичный HTTPS Backend. Письма регистрации и HTTP-модерация с реальными постоянными аккаунтами требуют проверки на общем опубликованном домене. Локальная браузерная QA использует отдельный изолированный стенд с вымышленными аккаунтами и подменёнными внешними сервисами; реальные Supabase/Render отдельно прошли 37 интеграционных проверок.
