# Подключение готовых агентов к приложению

1. Откройте https://keme-ai.onrender.com/catalog/ и выберите готового агента → «Подключить».
2. Войдите в аккаунт бизнеса, опишите задачу и отправьте запрос на доступ. Модератор одобряет запрос в кабинете администратора.
3. Загрузите нужные документы в кабинете. После одобрения в разделе «Подключить к своему приложению» выберите агента, задайте правила, язык, документы и срок действия ключа.
4. Создайте API-подключение. Скопируйте показанный один раз ключ в секреты своего серверного приложения.
5. В LLM-клиенте с поддержкой Custom OpenAI задайте:

| Поле | Значение |
| --- | --- |
| Base URL | `https://keme-ai-platform.onrender.com/api/agents/support/v1` для Support. Для Marketing и HR укажите `marketing` или `hr` в том же месте. |
| API key | Отдельный `keme_…` ключ из кабинета |
| Model | `keme/support`, `keme/marketing` или `keme/hr`, в соответствии с выбранным агентом |
| Streaming | Выключен |

К Base URL добавляются пути `GET /models` и `POST /chat/completions`. Запрос принимает `model`, `messages` (текст с ролями system/user/assistant) и `stream: false`. Tools, изображения, аудио и другие параметры возвращают 422. Ранее настроенные клиенты могут продолжать обращаться по общему Base URL `/api/v1`.

```bash
curl 'https://keme-ai-platform.onrender.com/api/agents/support/v1/chat/completions' \
  -H "Authorization: Bearer $KEME_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"keme/support","messages":[{"role":"user","content":"Какие условия доставки?"}],"stream":false}'
```

Инструкции задачи, язык и выбранные документы применяются сервером к каждому запуску. Клиент не может заменить агента или список документов через тело запроса. Для изменения настроек создайте новое подключение и отзовите старое. До выполнения каждый раз проверяются действительность ключа, текущая роль владельца, доступность карточки и одобрение доступа компании к агенту. Удалённый документ делает запуск с ним недоступным.

Ключ действует 90 дней по умолчанию (можно выбрать 30 дней или год). Хранится только SHA-256 случайного 256-битного ключа. Ключ показывается сразу после создания. В «Истории подключений» доступны заявки с их статусами и ссылками на агентов, а для API-подключений — адрес, модель, статус и префикс ключа. Для вызова проверяются тип агента в URL и модель в запросе. Отзыв блокирует новые запросы; уже принятый запуск может закончиться. Выход из браузера не отзывает отдельные ключи приложения. Ключ не даёт доступ к аккаунту, созданию других ключей, просмотру всех документов или чужим агентам. Не размещайте его в публичном JavaScript или URL. Публичная ссылка `/account/?agent=support` открывает выбранного агента без передачи учётных данных.

Таблица `agent_integrations` доступна только серверу через service role; RLS включён, привилегии anon/authenticated отозваны. Все операции управления дополнительно ограничены `user_id` и `company_id` проверенного пользователя. В текущей модели `company_id = user_id`. API-ключи не заменяют Supabase Auth и не раскрывают JWT_SECRET движка. Параметры задачи и ссылки на документы хранятся в этой закрытой таблице; тексты запросов и ответов не записываются в журнал agent_runs.

Запуски проходят через существующие журнал, квоты и AI Engine. В текущем облачном стенде ответы демонстрационные (`keme.mode = mock`); подключение API само по себе не включает реальную модель. Ответ содержит стандартные `choices`/`usage` и дополнительный объект `keme` со статусом, режимом и признаками сохранения журнала. Ошибки остаются в формате платформы `error.code/message`; POST не повторяется автоматически. На бесплатном Render первый API-запрос после простоя может занять около минуты; установите таймаут до 180 секунд.

Управление: `GET /integrations`, `POST /integrations`, `DELETE /integrations/{id}` используют Supabase access token аккаунта бизнеса. Имеются соответствующие пути с префиксом `/api`. Endpoint Base URL формируется интерфейсом из конфигурации публичного API. Пример в кабинете использует плейсхолдер ключа и не включает реальный секрет.
